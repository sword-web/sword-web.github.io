# Tonic Fundamentals

Sword uses `tonic` as its foundation for gRPC. This guide summarizes what you need to understand when creating gRPC controllers in Sword.

## What does Tonic generate from a `.proto` file?

When you compile your `.proto` file, Tonic generates:

- A service trait (e.g., `UserGrpcService`).
- A server to register the service (e.g., `UserGrpcServiceServer<T>`).
- Request/response types and enums defined in the contract.

## What do you implement in Sword?

In Sword, you implement the trait generated by Tonic within a controller annotated with `#[controller(kind = Controller::Grpc, ...)]`.

```rust
use sword::grpc::*;
use sword::prelude::*;

#[controller(kind = Controller::Grpc, service = UserGrpcServiceServer)]
pub struct UsersController;

#[sword::grpc::async_trait]
impl UserGrpcService for UsersController {
    async fn get_user(
        &self,
        _: Request<GetUserRequest>,
    ) -> GrpcResult<GetUserResponse> {
        Ok(Response::new(GetUserResponse { user: None }))
    }
}
```

## Base types in gRPC methods

For unary methods, the general form is:

- Input: `Request<T>`
- Output: `GrpcResult<U>` (which is `Result<Response<U>, Status>`)

This allows you to:

- Access request metadata.
- Return typed responses.
- Return gRPC errors using `Status`.

## Unary vs Streaming (Quick overview)

- **Unary**: One request, one response.
- **Streaming**: One request and multiple responses (or vice versa, depending on the contract).
